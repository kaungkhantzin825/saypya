### New hard-won rules

- **`grid` without a `grid-cols-*` class creates an implicit `auto` track that is floored at
  the content's min-content width.** `min-w-0` on the *container* does not help — the
  container's own track still sizes to its children, so a 436px card inside a 358px column
  pushes the whole page wide. Tailwind's `grid-cols-1` is `repeat(1, minmax(0, 1fr))`, which
  removes the floor. **Every bare `grid` container in a page must carry `grid-cols-1`.**
  Symptom: `documentElement.scrollWidth > innerWidth`; diagnose with
  `.workbuddy-ai/diag-chain.cjs <url>`, which prints each ancestor's width and
  `gridTemplateColumns`. Verified: all 13 admin pages now fit 390px.
- **reka-ui throws on a `SelectItem` whose value is the empty string** ("must have a value
  prop that is not an empty string") and the whole Select stops working. Never model an
  empty row as an option — use the `placeholder` prop on `<Select>`.
- **`request()->ajax()` is true for Inertia requests**, so a controller branch
  `if ($request->ajax()) return response()->json(...)` swallows the Inertia response and the
  page dies with "All Inertia requests must receive a valid Inertia response". Guard with
  `if ($request->ajax() && ! $request->header('X-Inertia'))`. Applied to all 9 such branches
  in `AdminController` (course sections/lessons + exam questions).
- **Inertia serialises a `null` field to `""`** (`objectToFormData` → `append(key, "")`), and
  `ConvertEmptyStringsToNull` turns that into `null`. So an `update($validated)` that includes
  a file column **silently wipes it** whenever no new file was picked. `updateBlogPost` had
  exactly this bug and cleared `featured_image` on every edit. Fix: `unset()` the file key and
  only set it when `hasFile()` — the pattern `coursesUpdate`/`usersUpdate`/`categoriesUpdate`
  already used (`$request->only([...])` + explicit file handling).

## Test-harness gotchas (cost me several runs)

- **Do not edit anything under `resources/` while a browser test is running.** The Laravel Vite
  plugin full-reloads the page on `.blade.php`/asset changes, which aborts an in-flight
  `page.goto` with `net::ERR_ABORTED`. Delete Blade files and edit Vue files *before* starting
  a run. Test scripts live in `.workbuddy-ai/` and are safe to write mid-run.
- **The shell kills commands at 120s.** A full Playwright suite takes 1.5–4 min, so always use
  `run_in_background: true`.
- Git Bash rewrites `/admin/...` CLI args into Windows paths — prefix with `MSYS_NO_PATHCONV=1`.

## Batch 5 — Exams cluster migrated to Vue/Inertia (`.workbuddy-ai/exams-check.cjs`, 31/31)

**Verified twice:** once before deleting the Blade views, and again after the backup + delete +
`build-safe.mjs` rebuild — still 31/31, which is what proves nothing was still resolving

Pages: `Admin/Exams/{Index,Form,Results,Grade}.vue`. `Form` is shared by create and edit and

only add and delete, so editing a typo meant deleting and retyping the question.
`examsIndex|examsCreate|examsEdit|examsResults|examsGrade` converted to `Inertia::render`.

Five real bugs found and fixed while converting:

1. **`examsIndex` lazy-loaded every question set.** The Blade called
   `$exam->questions->count()` per row with no `withCount`. Now `withCount(['questions','attempts'])`.
2. **Exam `title` was `nullable` in validation but `NOT NULL` in the schema.** An empty title
   reached the INSERT and died with a 1048 integrity error. Both `examsStore` and `examsUpdate`
   now use `required`.
3. **Results stats were computed from the paginator.** `$attempts->count()` and
   `$attempts->where('passed', true)->count()` only ever saw the current page, so every number
   on the page was wrong once an exam passed 20 attempts. Replaced with one aggregate query.
   *Gotcha:* the aggregate aliases must not be `passed` or `total_points` — both are in
   `ExamAttempt::$casts` and would be coerced to booleans. Use `passed_count` etc.
4. **`score / total_points` divided by zero** on an exam with no points. The page now uses the
   existing `ExamAttempt::getPercentageAttribute()` (which guards) via
   `$attempts->getCollection()->each->append('percentage')`.
5. **`required_if:type,multiple_choice|array|min:2` on `options` is wrong.** `required_if` only
   drops the *required* check — `min:2` still runs on a present-but-empty array, so a true/false
   or essay question only passed because the old Blade leaked two blank `options[]` inputs.
   Replaced with `exclude_unless:type,multiple_choice|required|array|min:2`.

Also: the course picker only lists published courses, so editing an exam whose course was later
archived rendered an empty Select and silently reassigned the course on save — the exam's own
course is now pushed into the list.

### New rules learned

- **A destructive dialog must close in `onFinish`, not on click.** `destroyQuestion()` first
  closed the dialog immediately and then fired the DELETE, so a failure vanished silently. Caught
  by the suite: the SQL assertion ran before the request round-tripped.
- **`Button` + `href` is a `<Link>` → `getByRole('button')` times out.** Bit me on the results
  page's "Grade attempt" action; must be `getByRole('link', …)`. Same trap as the pilot batch.
- **Assert `coldComponent()` only after `coldGoto()`.** Clicking the grade link is an SPA visit,
  so `#app`'s `data-page` still named `Admin/Exams/Results`.
- **Toasts live ~7s, so three identical "Question added successfully" toasts in a row cannot be
  distinguished.** Waiting for the *dialog to hide* (driven by `onSuccess`) is the reliable
  success signal; only assert the toast when its text differs from the previous one.
- **reka-ui `Checkbox` is a `<button role="checkbox" data-state>`** (the hidden `<input>` only
  renders when `name` is set). Drive it by clicking when `data-state` differs, then assert.
- Aggregate stats need a fixture bigger than one page to be testable: the suite inserts 20 extra
  attempts and asserts the stat card reads 21 while the table shows 20 rows.

### Harness lesson: don't assert "hidden" with `innerHTML`

The first version of the check asserted `!document.body.innerHTML.includes('Why Sanpya')` and
failed. A probe (TreeWalker over `NodeFilter.SHOW_COMMENT`) showed the markup is present as a

strips them in production. `innerText` / element queries are the correct assertion for "not
rendered"; `innerHTML` matches comments and gives a false failure. Assert on rendered content,
not on raw markup.

near-empty one (48px, a single hyphen). `HeroSlide::scopeOrdered()` was already deterministic

### Follow-up: the scrim was washing the photo out

User feedback: *"Background will be seen full and white is too many so no clear to see."* The first
full-bleed scrim (`from-background via-background/90 to-background/40`) put white over the whole
band, so the photo was barely visible. Replaced with an explicit multi-stop gradient that is
near-opaque only behind the copy and reaches **full transparency by ~62%**, leaving the right of the
image untouched.

Then the mobile screenshot showed a second, worse problem the desktop view hid: below `lg` the copy
spans the full width, so a left-to-right fade left the right half of the subtitle sitting on bare
photo and it was illegible. The scrim direction is now **responsive** — top-to-bottom below `lg`,
left-to-right from `lg` up where the copy is confined to the left column.

Lesson: a horizontal scrim only works while the text is in a horizontal *column*. Check the narrow
breakpoint whenever a gradient is used for text contrast, and actually look at the mobile
screenshot — the desktop render was unchanged and told me nothing. `.workbuddy-ai/shot-hero.cjs`
captures desktop + mobile + dark in one pass for exactly this.
